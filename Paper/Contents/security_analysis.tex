\section{Security Analysis}
\label{sec:security}

We prove that the protocol $\protocol$ (Figure~\ref{fig:protocol}) constitutes a secure interactive argument for the matrix multiplication relation $\mathcal{R}_{\mathsf{orig}}$ over encoded input roots and the sampled-opening backend of Definition~\ref{def:codecom-backend}.
Soundness and completeness are established in Theorem~\ref{thm:security} below; knowledge soundness is discussed separately in Remark~\ref{rem:aok}.
As discussed in Section~\ref{sec:relation-chain}, the input roots $\cm_A,\cm_B,\cm_C$ bind to row-wise encodings of fixed matrices $\mat{A},\mat{B},\mat{C}$.
This is the committed-input model used by code-based proof systems such as Brakedown~\cite{golovnev2023brakedown} and Orion~\cite{xie2022orion}; $\protocol$ verifies the multiplication relation among these committed objects.
For the intermediate vectors, the prover sends pre-query vector commitments to
$\vect{x},\vect{y},\vect{z}$ before the query tuple is sampled.
At each sampled coordinate, the committed-witness SNARK backend binds the matrix
column or vector leaf used by the circuit to a public SNARK-side commitment
$\Gamma_{\chi,j}$.
The auxiliary verifier authenticates a compact external Merkle leaf handle
$L_{\chi,j}$ and checks that it is linked to the SNARK-side commitment.
For intermediate vectors, the SNARK also computes $\enc(v)_j$ internally before
the sampled value is linked to the authenticated handle.

\paragraph{Scope of the security claim}
The theorem is a statement-soundness result for committed matrix
multiplication, not a standalone argument-of-knowledge or zero-knowledge
theorem.
The public objects are the encoded input roots and the
transcript-derived challenges; the committed objects are the row-wise encodings
of $\mat{A},\mat{B},\mat{C}$ and the intermediate encoded vectors.
The backend supplies vector binding before $I$ and sampled consistency between
the SNARK-side commitments and the external Merkle openings.
Witness extraction and hiding require the additional composition assumptions
described in Remark~\ref{rem:aok} and are outside the main theorem.
In short, $\cm_A,\cm_B,\cm_C$ are input roots fixed before $r$;
$\mu_x,\mu_y,\mu_z$ and $\cm_x,\cm_y,\cm_z$ are fixed before $I$; sampled raw
columns are private Groth16 witness values linked to authenticated leaf handles.

\paragraph{Soundness-critical ordering}
The proof uses the following timing invariants.
First, the input roots $\cm_A,\cm_B,\cm_C$ are fixed before the
Freivalds challenge $r$ is sampled.
Second, the intermediate vector commitments and encoded-vector roots are fixed
before the query tuple $I=(j_1,\ldots,j_t) \sample [n]^t$ is sampled;
conditioned on an accepting vector-commitment opening proof, each vector
$\vect{x},\vect{y},\vect{z}$ is fixed independently of the sampled positions,
and accepted auxiliary linking proofs bind sampled external openings to the
corresponding SNARK-side commitments.
For intermediate vectors, the vector openings and in-circuit RS checks force
the value behind each SNARK-side commitment to be the corresponding coordinate
of $\enc(\vect{x}),\enc(\vect{y}),\enc(\vect{z})$.
Third, the entries of $I$ are sampled independently with replacement, as
defined in Section~\ref{sec:notation}.
If an implementation samples without replacement, the proximity failure
probability only decreases; the theorem states the simpler with-replacement
bound.

\paragraph{Backend failure event}
The backend bad event is the only non-standard composition point.
After the transcript prefix fixes
$(\mathsf{Cm}_{ABC},r,\mathsf{Cm}_{XYZ},I)$, the adversary must output
SNARK-side commitments, Merkle openings, and an auxiliary linking proof for the
sampled objects.
A backend failure occurs if all these checks accept while some value used in
the Groth16 fold relation is not the value authenticated at the corresponding
leaf position.
Definition~\ref{def:codecom-backend} charges this event to
$\epsilon_{\mathsf{cc}}$; Appendix~\ref{app:security-proof} expands the event
for the concrete backend.
For the artifact backend summarized in Section~\ref{sec:construction}, the
sampled-linking component contributes
$\epsilon_{\mathsf{link}}\le
\epsilon_{\mathsf{ped}}+\epsilon_{\mathsf{QA}}+Q/|\mathbb{F}|$, where
$Q=|\mathcal{S}|t$ is the number of sampled SNARK-side/leaf commitment pairs.
Here $\epsilon_{\mathsf{ped}}$ is the binding error of the algebraic handle
parameters, $\epsilon_{\mathsf{QA}}$ is the soundness error of the batched
QA-NIZK relation, and the $Q/|\mathbb{F}|$ term is the standard randomized-batch
failure probability after the batch statement is fixed.

\begin{theorem}[Security]\label{thm:security}
The protocol $\protocol$ satisfies the following properties:
\begin{enumerate}[label=(\roman*)]
  \item \textbf{Perfect completeness.} If $\mat{A}\mat{B} = \mat{C}$, an honest prover always makes the verifier accept.
  \item \textbf{Interactive computational soundness.}
  For any $\ppt$ adversary $\mathcal{P}^*$ given public input
  roots for $\mat{A},\mat{B},\mat{C}$, let $\mathsf{Acc}$ be the event
  that the verifier accepts a false committed matrix statement.
  Then:
\[
\begin{aligned}
\Pr[\mathsf{Acc} \mid \mat{A}\mat{B} \neq \mat{C}]
&\le
\epsilon_{\mathsf{SNARK}}(\lambda)
+ \epsilon_{\mathsf{cc}}(\lambda)
+ \epsilon_{\mathsf{bind}}(\lambda) \\
&\quad + \frac{k-1}{|\mathbb{F}|}
+ 4(1 - \delta)^{t},
\end{aligned}
\]
Here $t = |I|$ is the query complexity and $\delta$ is the relative minimum
distance of $\mathcal{C}$.
The terms $\epsilon_{\mathsf{SNARK}}$, $\epsilon_{\mathsf{cc}}$, and
$\epsilon_{\mathsf{bind}}$ denote, respectively, the soundness error of the
SNARK backend including committed-witness binding, the
vector-binding/linking consistency error of the selected intermediate backend,
and the union-bounded position-binding error of the opening layer over all roots
and openings used in the protocol.
  In the notation of Definition~\ref{def:codecom-backend},
  $\epsilon_{\mathsf{cc}}\le
  \epsilon_{\mathsf{vec}}+\epsilon_{\mathsf{link}}$.
  For the artifact backend,
  $\epsilon_{\mathsf{link}}\le
  \epsilon_{\mathsf{ped}}+\epsilon_{\mathsf{QA}}+|\mathcal{S}|t/|\mathbb{F}|$;
  Appendix~\ref{app:cplink-backend} gives the full batching equation.
  \item \textbf{Fiat--Shamir soundness.} In the random oracle model, the
  non-interactive variant described in Section~\ref{sec:protocol-desc}
  satisfies the same bound with an additional Fiat--Shamir loss term
  $\epsilon_{\mathsf{FS}}(q_H)$, where $q_H$ is the adversary's number of
  random-oracle queries.
\end{enumerate}
\end{theorem}

\begin{corollary}[Evaluated backend]\label{cor:evaluated-backend}
For the backend used in the artifact, Theorem~\ref{thm:security} applies with
\[
  \epsilon_{\mathsf{cc}}
  \le
  \epsilon_{\mathsf{vec}}
  +\epsilon_{\mathsf{ped}}
  +\epsilon_{\mathsf{QA}}
  +|\mathcal{S}|t/|\mathbb{F}|.
\]
The bound assumes the pre-query vector commitment is binding, the algebraic handle
parameters are binding, the QA-NIZK is sound for the stated linear batch
relation, and the batch randomizer is sampled after the commitment-pair statement is
fixed.
In the non-interactive artifact, the Fiat--Shamir loss term
$\epsilon_{\mathsf{FS}}(q_H)$ covers both the protocol challenges $(r,I)$ and
the backend batch randomizer, using separate domain tags.
\end{corollary}

The reported scaling rows use $t=128$; if $\delta=1/2$, this gives proximity
term $2^{-126}$, while a conservative per-term $2^{-131}$ target uses $t=133$.
A strict deployment must also instantiate the SNARK, pre-query vector commitment,
sampled-linking backend, and hash parameters so their union-bounded errors fit
the aggregate security budget.

\paragraph{Proof sketch}
Completeness follows from linearity of the Freivalds reduction and of the
encoding: honest openings satisfy every sampled fold and equality check.
For soundness, condition away SNARK, vector-binding/linking, and position-binding
failures.
Then the input roots fix $\mat{A},\mat{B},\mat{C}$ before $r$, the intermediate
commitments fix $\vect{x},\vect{y},\vect{z}$ before $I$, and accepted sampled
openings are the same values used by the Groth16 fold relation.
Schwartz--Zippel gives the Freivalds term $(k-1)/|\mathbb{F}|$; conditioned on
Freivalds not failing, at least one of the four encoded relations is false, so
$t$ random coordinates miss its disagreement set with probability at most
$(1-\delta)^t$.
Union-bounding over the four relations gives the proximity term.
Appendix~\ref{app:security-proof} gives the detailed proof and the
Fiat--Shamir random-oracle reduction.

\begin{remark}[Fiat--Shamir soundness]\label{rem:fs-soundness}
The proof of the main bound in Theorem~\ref{thm:security} is for the
public-coin interactive protocol.
The non-interactive variant in Section~\ref{sec:protocol-desc} derives both
$r$ and $I$ from domain-separated hashes of the full transcript prefix.
The artifact backend also derives its batch randomizer with a separate domain
tag after the commitment-pair batch statement is fixed.
In the random oracle model, the same proof applies with the standard
Fiat--Shamir loss $\epsilon_{\mathsf{FS}}(q_H)$, where $q_H$ is the adversary's
number of random-oracle queries.
This term accounts for grinding over transcript prefixes and is negligible for
polynomial $q_H$ when the challenge and query hashes have $\lambda$-bit
security.
\end{remark}

\begin{remark}[Knowledge Soundness]\label{rem:aok}
The theorem above is a statement-soundness result relative to input roots that
bind to row-wise encoded matrices.
A full \emph{argument of knowledge} can be obtained by composing $\protocol$ with an extractable input-commitment interface and a knowledge-sound SNARK.
In that setting, the input-commitment extractor yields openings of $\cm_A,\cm_B,\cm_C$ to row-wise encoded matrices, while the SNARK extractor yields the intermediate vectors and queried openings used in $\mathcal{R}_{\mathsf{Prox}}$.
The same soundness argument then implies that any prover accepted with non-negligible probability is bound, except with the stated error, to matrices satisfying $\mat{A}\mat{B}=\mat{C}$.
We treat this as an orthogonal composition issue and focus the main theorem on the multiplication-checking protocol.
\end{remark}
