\section{Implementation and Evaluation}
\label{sec:implementation}

We implement the multiplication-checking layer of $\protocol$ and evaluate the
current artifact, denoted $\fmQA$, against an optimized SNARK-in-circuit
Freivalds baseline~\cite{freivalds1977probabilistic}.
$\fmQA$ uses multi-column Merkle openings, a Groth16 circuit proof, and a
QA-NIZK/CP-link layer that connects public Groth16 wire handles to opened
external Merkle leaf handles.
All main experiments use a 256-bit prime field, rate $\rho=1/2$, codeword
length $n=2k$, and $t=128$ sampled positions.
The experiments were run on a Linux server with an AMD EPYC 7B13 CPU
(32 cores) and 254\,GB RAM.

These measurements include the online sampled-handle path described in
Section~\ref{sec:construction}: message commitments fix
$\vect{x},\vect{y},\vect{z}$ before $I$, the circuit binds every sampled
matrix column or vector leaf to a public wire handle, Merkle openings
authenticate compact external leaf handles, and QA-NIZK/CP-link checks connect
the two views.
The raw sampled matrix columns are SNARK witness data, not serialized auxiliary
proof bytes.
They do not include raw input certification for
$\cm_A,\cm_B,\cm_C$ and should not be read as complete end-to-end deployment
costs from raw matrices.
Appendix~\ref{app:eval-details} records parameter and measurement coverage
details.

\paragraph{Primary matrix benchmark}
Figure~\ref{fig:main-benchmark} shows the main scaling behavior.
Freivalds constraints grow by approximately $4\times$ with each doubling of
$k$, matching the expected $\mathcal{O}(k^2)$ scaling.
In contrast, $\fmQA$ grows by approximately $2\times$, matching the
$\mathcal{O}(k)$ checking-layer scaling of the CP-linked sampled-opening
backend.
The crossover in absolute constraint count occurs at $k=256$.
At $k=1{,}024$, $\fmQA$ uses $419{,}139$ constraints versus $3{,}156{,}298$
for Freivalds, a $7.53\times$ reduction.
At $k=4{,}096$, $\fmQA$ uses $1{,}667{,}305$ constraints versus
$50{,}495{,}818$ for Freivalds, a $30.29\times$ reduction.

The same benchmark shows a proving-time crossover at $k=256$.
At $k=4{,}096$, $\fmQA$ proves in $56.44\,\text{s}$ versus
$405.04\,\text{s}$ for Freivalds, a $7.18\times$ speedup.
$\fmQA$ also completes $k=8{,}192$ with $3{,}331{,}779$ constraints and a
$178.48\,\text{s}$ proving time; Freivalds was not measured at that size in the
current artifact.

\paragraph{Verification, proof size, and GPT-2 workload}
$\fmQA$ verification is nearly constant at about $0.10\,\text{s}$ in the matrix
benchmark, dominated by QA-NIZK link verification; Freivalds verification is
faster because it checks only a direct Groth16 proof.
The artifact therefore trades slower verification for smaller prover circuits
and faster proving at medium and large dimensions.
The $\fmQA$ online proof grows from $15{,}108$ bytes at $k=128$ to
$104{,}388$ bytes at $k=4{,}096$ and $125{,}508$ bytes at $k=8{,}192$.
At $k=4{,}096,t=128$, publishing the three sampled input-matrix columns alone
would require about $3tk\cdot32\approx50$\,MB; Appendix~\ref{app:eval-details}
gives detailed byte, setup, and constraint accounting.

Figure~\ref{fig:gpt2-case-study} and Table~\ref{tab:gpt2-case-study} report the
GPT-2-style workload over certified roots. $\fmQA$ reduces constraints by
$2.30\times$ and proving time by $1.77\times$, with lower setup time in this
experiment. Verification remains slower, so latency-sensitive deployments still
need batching, amortization, or a more succinct opening/linking backend.

\paragraph{Strict parameters and deployment scope}
The measured rows use $t=128$ to study scaling. If $\delta=1/2$, a conservative
per-term $2^{-131}$ proximity budget uses $t=133$, increasing sample-dependent
work by only $1.0391\times$.
At $k=4{,}096$, this extrapolates to at most $1.74$ million constraints,
$58.65\,\text{s}$ proving time, and $109$\,KB online proof bytes.
Proof-size figures exclude raw input certification, proving/verifying keys, and
serialized CRS or generator material. End-to-end deployments preserve the
measured prover-time win only if amortized root certification costs stay below
the observed margins: $348.60\,\text{s}$ for $k=4{,}096$ and $178.36\,\text{s}$
for the GPT-2 row.
